# Invest Platform

Инвестиционно-исследовательская платформа (PWA). Next.js 14 App Router +
TypeScript + Tailwind CSS.

## Архитектурный принцип

**Вся финансовая математика — чистые функции в `src/lib/calculations/`.**
UI-компоненты и любой будущий AI-слой объяснений только читают уже
посчитанные результаты, никогда не считают цифры сами. Если нужно
добавить новую метрику — добавляй функцию в `lib/calculations/`, а не
считай inline в компоненте.

Единая точка доступа к данным — `src/lib/data/dataService.ts`. Сейчас
отдаёт мок-данные синхронно, но интерфейс уже async — при подключении
реального API (например Alpha Vantage) меняется только этот файл.

## Структура

```
src/
  app/                    Страницы (App Router)
  components/
    ui/                   Card, Badge, PnlValue, Sparkline, StatTile
    portfolio/             PortfolioSummary, AllocationBar, HoldingsList, HoldingRow
    layout/                AppHeader, BottomNav, ServiceWorkerRegistration
  lib/
    calculations/          portfolioMetrics.ts — вся математика портфеля
    data/                  mockPortfolio, mockPriceHistory, dataService
    utils/                 cn, format, assetClass
  types/                   portfolio.ts
public/
  icons/                   PWA-иконки (192, 512, maskable-512)
  manifest.json            PWA manifest
  sw.js                    Service worker — кэширует только shell, НЕ данные
```

## PWA

`manifest.json` + `sw.js` подключены, `apple-icon.png`/`icon.png` в
`src/app/` (Next.js их подхватывает автоматически). Service worker
кэширует только shell (`/`, `/manifest.json`) для офлайн-загрузки
приложения — рыночные данные принципиально НЕ кэшируются офлайн, чтобы
не показывать устаревшие цифры без явного предупреждения.

## Проверка консистентности перед коммитом/архивом

Сеть в среде агента не даёт прогнать `npm install` / `next build`
напрямую — единственная доступная проверка до пуша на Vercel:

```bash
scripts/check-imports.sh
```

Скрипт проверяет: 1) каждый `@/...` импорт резолвится в реальный файл
на диске (с учётом регистра), 2) при импорте конкретных именованных
экспортов — что они реально есть в целевом файле, 3) список файлов, на
которые никто не ссылается (не ошибка, но сигнал мусора).

**Это не замена `next build`.** Первый деплой на Vercel всё равно может
найти то, что статический грep не ловит (типы, синтаксис JSX,
несовместимость версий пакетов). Но это резко снижает число "глупых"
циклов правка→пуш→ждать→лог.

## Развёртывание

1. Скачать zip, распаковать.
2. Залить содержимое (НЕ вложенную папку — `package.json` должен быть в
   корне репозитория) в GitHub через web upload.
3. Подключить репозиторий к Vercel, framework preset — Next.js
   (определится автоматически).
4. Первый деплой — смотреть лог сборки на Vercel, не гадать локально.
